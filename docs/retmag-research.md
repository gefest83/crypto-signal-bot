# RetMag — что проверено, что нет

Исследование taker-стратегии для рынков BTC/ETH Up/Down 5m.
Дата: 2026-09-27. Данные: локальный кэш `scripts/.cache/`.

Конвейер: `bun scripts/retmag.ts` (направление) и `bun scripts/retmag-live.ts`
(сверка с исполнимой ценой). Оба — research-only, торговли не делают.

## Правило

```
t      = round_start + 20s
window = (t - 30s, t]
imb    = 2*buy/vol - 1              <- имбаланс, центрирован на 0
ret20  = (close@t - close@round_start) / close@round_start

|imb| >= 0.25                     -> сторона = sign(imb)
sign(ret20) == sign(imb)          -> обязательно (agree_ret20)
|ret20| >= 2.0 bps                -> НОВЫЙ гейт, иначе HOLD
ask <= 0.60 (BTC) / 0.70 (ETH)    -> потолок цены
```

## Две ошибки, которые стоили двух ложных выводов

Записаны здесь намеренно: обе выглядели как «стратегия не работает» и обе
были дефектом порта, а не данных.

**1. Доля вместо имбаланса.** Первый вариант использовал `buy/vol` — это доля,
центрированная на 0.5. При пороге `|flow| >= 0.25` условие выполнялось в 76%
раундов, а `flow <= -0.25` не выполнялось **никогда** (`n=0`). Сторона сигнала
оказалась прибита к UP, и «имбаланс» не измерял ничего. Правильно:
`2*buy/vol - 1`, где 0.25 означает 62.5% объёма у тайкеров.

**2. Hit rate считался по чужой стороне.** «Без гейта» считалась победа по
`gated`-стороне, поэтому все заблокированные раунды уходили в убытки. Отсюда
идиотические 34.8% — выглядело, будто базовое правило работает наоборот.
На деле оно симметрично: `ret<0 & imb<0` → UP выигрывает 33.6%, то есть
DOWN 66.4%.

Обе проверки теперь встроены в `retmag.ts` как sanity-assertions, чтобы
подобное не проскочило молча.

## Что подтверждено

**Сигнал направления настоящий.** 576 раундов на актив (1s свечи есть только
за 2 дня — не за 30):

| | без гейта | с гейтом |
|---|---|---|
| BTC | 65.5% (n=325) | 69.3% (n=163) |
| ETH | 67.7% (n=266) | 71.2% (n=153) |

Против монетки — z ≈ 7, не шум. `sign(ret20)` сам по себе совпадает с исходом
в 61.6% / 65.3% случаев.

**Спред нормальный.** Замер живого раунка: 1 тик, 80–100 уровней ask,
ask присутствует в 10/10 замеров. То есть вход около mid+1 тик — не fiction,
а примерно реальная цена. При входе 0.50 один тик = ~2% от номинала, то есть
ровно сопоставимо с комиссией 200bps.

**Рынок откалиброван.** Цена на +15s против исхода:

```
цена ~0.4 → исход 40.1%   разрыв +0.1 п.п.
цена ~0.5 → исход 49.0%   разрыв −1.0 п.п.
цена ~0.6 → исход 59.3%   разрыв −0.7 п.п.
цена ~0.7 → исход 71.3%   разрыв +1.3 п.п.
```

Разброс ±3 п.п. по всем бакетам.

## Что НЕ подтверждено

**Гейт `|ret20| >= 2bps` не работает как заявлено.** Даёт +3.8 п.п. (BTC) и
+3.5 п.п. (ETH) к hit rate, но z = 0.85 и 0.77 — на такой выборке это
неотличимо от шума. При этом он вдвое срезает число сделок (325→163, 266→153).
Ради +3.5 п.п., которых нельзя отличить от случайности, выбрасывается
половина торговли. Валюта стратегии — сделка на сделку, а не процент
попаданий.

**Не установлено, зарабатывает ли стратегия вообще.** Рынок откалиброван
(±3 п.п.), значит сигнал с 69% при входе около 0.50 — это не преимущество
на 19 п.п., а несоответствие. Разрывы по бакетам входа:

| вход | исход | разрыв с ценой | n | z |
|---|---|---|---|---|
| BTC 0.45–0.55 | 60.7% | +10.7 п.п. | 56 | 1.6 |
| BTC 0.55–0.65 | 74.3% | +14.3 п.п. | 35 | 1.9 |
| ETH 0.55–0.65 | 78.3% | +18.3 п.п. | 46 | 3.0 |
| ETH 0.65+ | 85.7% | +2.7 п.п. | 21 | 0.35 |

Прогонялось ~6 бакетов, так что z=3.0 при множественных сравнениях даёт
примерно p=0.017 — **на грани, но не доказательство**. P&L в $2.50 на сделку
из `retmag.ts` — прямое следствие этих +18 п.п. на откалиброванном рынке,
то есть цифра нереальна. Не считать.

## Почему нельзя пересчитать задним числом

- Книга закрытого рынка **пуста**. Замер: 99 bids и **0 ask'ов** — покупать
  нечем. Первый замер спреда я сделал именно на таком схлопнувшемся раунде и
  почти сделал из этого вывод, что рынок неторгуемый.
- `data-api/trades` отдаёт `[]` и для текущего, и для суточного рынка.
  Исторических исполненных сделок по этим токенам нет.
- С терминала CLOB отдаёт 403 по IP (в начале сессии отвечал).

Единственный честный источник — наблюдать стакан в момент, когда рынок жив.

## Что построено для этого

- `pmQuotes` — таблица сырых снимков стакана, **не per-user**: котировка это
  факт о рынке, и per-user-привязка сделала бы архив описанием того, сколько
  людей смотрели, а не того, что делал рынок.
- `archiveQuote` — **публичная, без auth**. С auth-guard архив покрывал бы
  только периоды с открытой вкладкой, и измеряемое преимущество стало бы
  невоспроизводимым.
- Хук пишет в окне +12…+45с — только то, что окружает точку решения +20s.
- `retmag-live.ts` считает **edge против цены**: `hit − ask` на $1 стейка за
  вычетом 200bps и 0.005/шар.

Защитные дефолты, которые нельзя ослаблять: неизвестный исход раунда
возвращает `null`, а не `false` (иначе пустые данные дают правдоподобный
отрицательный результат); раунд без котировки падает в `no quote`, а не
заменяется mid'ом.

## Состояние на момент остановки

`pmQuotes` пуст. Аналитическая часть `retmag-live.ts` на реальных данных
**не проверена** — писалась вслепую, первый прогон может потребовать починки.

Для проверки нужно ~300+ сделок на бакет, то есть сутки-двое непрерывно
открытой вкладки. Данные появляются только пока кто-то смотрит.

## Конфликт с текущим проектом

Это **тейкер**-стратегия с комиссией 200bps — прямая противоположность
maker-подходу, который реализован в этом репозитории (`src/lib/strategy/`).
На откалиброванном рынке тейкер с 200bps проигрывает maker-у по определению,
если сигнал не бьёт рынок на толщину комиссии.
